# Voice pipeline: запуск и эксплуатация

## Статус

Контур `Voximplant → streaming STT → parallel LLM orchestration → Fish Audio`
реализован и проверяется локально одной командой. Для live-приёмки нужны
внешние аккаунты, ключи, публичный TLS-домен и телефонный номер; эти секреты не
хранятся в репозитории.

Текущий production-путь использует hosted API. H100 — отдельный следующий этап
для self-hosted моделей после измерения реальной нагрузки. Контракты
`StreamingSttProvider`, `ModelRunner` и `StreamingTtsProvider` уже отделяют
провайдеры от телефонного state machine.

## Архитектура и гарантии

1. Voximplant открывает `wss://<host>/ws/voice`, подписывая соединение
   заголовком `X-Voice-Token`. `orgId` берётся только из серверной конфигурации,
   а не из недоверенного запроса.
2. Аудио звонка всегда передаётся как mono G.711 μ-law, 8 kHz.
3. Deepgram Flux работает как основной STT. Если его WebSocket не открылся до
   первого принятого аудио, система может один раз переключиться на AssemblyAI.
   После начала аудио переключение запрещено, чтобы не повторять или не терять
   реплики.
4. Turn Manager выдаёт монотонный номер поколения. Новая речь клиента сначала
   инвалидирует старое поколение, затем отменяет LLM/TTS и очищает playback.
5. Fast и medium запускаются параллельно. Fast не ждёт RAG. Deep запускается
   только по оценке сложности, классификатору или запросу medium.
6. В речь попадают только безопасные подтверждённые сегменты. Значение, уже
   произнесённое клиенту, нельзя позднее заменить противоречащим значением.
7. Fish Audio отдаёт поток PCM, backend преобразует его в телефонный μ-law.
   Завершение ответа подтверждается playback ACK от Voximplant.
8. Все очереди, входящие кадры, запись звонка и WebSocket buffers ограничены.
   При overflow звонок завершается явно — аудио не отбрасывается молча.
9. Graceful shutdown прекращает приём новых звонков и до 15 секунд ожидает
   `runtime.disconnect()`, сохранение записи в S3 и финализацию разговора в БД.

## 1. Подготовить `.env`

Скопируйте `.env.example` и заполните как минимум:

```dotenv
VOICE_RUNTIME=pipeline
VOICE_DEFAULT_ORG_ID=<UUID организации>
VOICE_WS_AUTH_TOKEN=<случайный секрет длиной 32+ символа>

ANTHROPIC_API_KEY=<ключ>
DEEPGRAM_API_KEY=<ключ>
ASSEMBLYAI_API_KEY=<опциональный резервный ключ>
FISH_API_KEY=<ключ>
FISH_TTS_REFERENCE_ID=<разрешённый reference voice>

WEBHOOK_BASE_URL=https://voice.example.com
VOXIMPLANT_ACCOUNT_ID=<account id>
VOXIMPLANT_API_KEY=<management api key>
```

Секрет можно создать командой `openssl rand -hex 32`. Используйте только голос,
на который есть необходимые права и согласие. Первое приветствие должно
оставаться прозрачным: пользователь должен понимать, что разговаривает с
виртуальным помощником.

## 2. Проверить код

```bash
npm install
npm run verify:voice
```

Команда последовательно выполняет:

- ESLint;
- TypeScript typecheck приложения и тестов;
- весь voice test-suite;
- production build;
- синтаксическую проверку VoxEngine и setup-скрипта;
- `git diff --check`.

## 3. Проверить Fish Audio

```bash
npm run smoke:fish-tts
```

Прослушайте `/tmp/fish-tts-smoke.wav`. До live-звонка проверьте произношение
названия компании, имён, чисел, цен, дат и адресов.

## 4. Развернуть backend

- Нужен Node.js 20+, PostgreSQL, Redis и S3-совместимое хранилище.
- `WEBHOOK_BASE_URL` должен быть публичным `https://`; соответствующий
  `wss://` endpoint должен принимать upgrade на `/ws/voice`.
- Reverse proxy должен передавать заголовок `X-Voice-Token`, не буферизовать
  WebSocket и иметь timeout больше максимальной длительности звонка.
- Проверьте, что в организации есть активный агент с каналом `voice`.
- В `voice_config.fish_reference_id` можно задать голос конкретного агента;
  иначе используется `FISH_TTS_REFERENCE_ID`.

## 5. Настроить Voximplant

```bash
npm run setup:voximplant
```

Скрипт идемпотентно создаёт или обновляет приложение и сценарий, создаёт правило
и повторно привязывает к нему актуальный сценарий. Покупка и привязка номера
остаются явным действием владельца аккаунта.

## 5.1. Проверить production readiness

После развёртывания выполните безопасную read-only проверку зависимостей:

```bash
npm run build
npm run --silent readiness:production -- \
  --env-file .env.production \
  --public-url https://voice.example.com \
  --strict
```

Команда проверяет production-конфигурацию, PostgreSQL 16 и схему с
`vector(768)`, Redis, оба S3 bucket, активного voice-агента, свежий публичный
`/health` и обязательный отказ WebSocket при неверном токене. Вывод содержит
только идентификатор проверки, статус, безопасный код и длительность — без URL,
UUID, ответов провайдеров и секретов. `--format json` включает машинный формат,
а `--billing` отдельно добавляет read-only проверки положительного баланса Fish
Audio и Voximplant; без этого флага обращения к их billing API не выполняются.
Entrypoint компилируется в `dist/readiness/cli.js` и запускается обычным Node.js,
поэтому он доступен в production-образе без `tsx` и каталога `scripts`.
Разделитель `--` в package script не даёт Node.js перехватить CLI-флаг
`--env-file`; прямой эквивалент — `node -- dist/readiness/cli.js ...`.
Для Docker Compose запускайте проверку через entrypoint нового контейнера
(не через `docker compose exec`, где вычисленный `DATABASE_URL` не наследуется):

```bash
docker compose run --rm app npm run readiness:production -- \
  --format json --strict --billing
```

Коды завершения: `0` — готово, `1` — есть блокер (или warning с `--strict`),
`2` — неверные аргументы/файл конфигурации, `3` — внутренняя ошибка, `130` —
проверка прервана пользователем.

## 6. Live-приёмка

Проведите минимум следующие звонки и сохраните логи:

- обычный вопрос и ответ;
- перебивание во время синтеза — старый звук должен прекратиться;
- вопрос, требующий RAG;
- сложный вопрос, активирующий deep;
- серия коротких реплик без дублирования transcript;
- отключение Fish до начала синтеза — один прозрачный native fallback;
- недоступный Deepgram при наличии AssemblyAI — fallback только до первого
  аудиофрейма;
- обрыв WebSocket и повторный звонок;
- звонок дольше типичного и проверка лимита записи.

Не объявляйте latency «мгновенной» до измерения реальных P50/P95. Для каждого
звонка контролируйте `voice_stt_connect`, `voice_tts_connect`,
`voice_tts_first_audio`, `voice_turn_total` и `voice_tts_fallback`, а также
orchestration-события по fast/medium/deep.

## Rollback

Если новый контур нестабилен:

1. Установите `VOICE_RUNTIME=gemini`.
2. Перезапустите backend без изменения Voximplant URL.
3. Не удаляйте сценарий и правило: оба runtime используют тот же
   авторизованный телефонный канал.
4. Сохраните call ID и структурированные логи для разбора.

Возврат на `pipeline` допустим только после `npm run verify:voice`, Fish smoke и
повторной live-приёмки.

## Что невозможно завершить без внешнего доступа

- подтвердить доступность конкретного Fish reference voice и права на него;
- измерить реальную задержку и естественность через телефонную сеть;
- купить/привязать номер Voximplant;
- проверить квоты, billing и лимиты внешних провайдеров;
- провести нагрузочный тест реальных API;
- проверить self-hosted inference на H100.

Эти пункты являются эксплуатационной приёмкой, а не незавершённым локальным
кодом.
